TraceOps · AgentOS Core Capability

企业智能体运行经验沉淀与自蒸馏系统

TraceOps 是 KodaX 生态中面向未来模型进化的数据底座。它记录的不只是聊天内容或系统日志， 而是 Agent 与 Harness 在真实企业任务中的完整协作过程，并将这些过程治理、提炼、标注、导出为可用于记忆、评测和训练的数据资产。

定位：AgentOS 底层数据资产能力 对象：KodaX CLI / Space / AgentOS 全链路 Trace 目标：可回放、可治理、可训练、可反哺 版本：概念设计稿 v0.1

一、核心判断

AgentOS 的价值不只是执行任务或管理智能体，而是把组织协同、项目推进和智能体运行过程沉淀成企业可持续复利的数据资产。

AgentOS 不是简单替代 Space 做端侧执行；它在组织和项目层完成规划、协同、分发、审批、治理与复盘，并把这些过程沉淀为可训练的企业 Trace。
不是日志

Trace 是执行经验

普通日志回答“发生了什么”，TraceOps 要回答“为什么这样做、怎么做、做得怎么样、下次如何做得更好”。

不是记忆库

Trace 是可训练资产

企业记忆沉淀结论和经验，TraceOps 保留任务从目标到结果的链路，能转化为 SFT、偏好、评测和工具调用数据。

不是监控

Trace 是进化闭环

监控关注状态和故障，TraceOps 关注高质量行为样本，并反过来优化 KodaX 内核、Skill、路由和项目拆解策略。

二、Trace 的定义

一次 Trace 是一次智能任务从产生、拆解、执行、审核、沉淀到反馈的完整链路。

Trace 包含什么
  • 用户原始意图、项目目标和业务上下文。
  • Agent 当时加载的角色配置、指令、Skill、工具、权限和记忆。
  • 计划、拆解、分发、工具调用、文件读写、命令执行、接口访问。
  • 失败、重试、人工确认、审批、纠偏、选择和放弃。
  • 最终产物、负责人评价、企业记忆候选和训练价值评分。
Trace 不应该是什么
  • 不是只保存聊天记录。
  • 不是只保存最终答案。
  • 不是未经脱敏就进入训练集的原始企业数据。
  • 不是脱离项目、成员、权限和业务目标的孤立日志。
  • 不是把所有数据无差别沉淀到全局记忆。
维度 普通日志 对话历史 TraceOps Trace
记录对象 系统事件和报错 用户与 Agent 的消息 目标、计划、工具、执行、反馈、评价的完整链路
主要用途 排障、审计、监控 上下文延续、问答回看 复盘、治理、提炼、评测、训练、自蒸馏
是否可训练 通常不可直接训练 质量不稳定，缺少工具和结果信号 经过治理和标注后可转化为多类训练数据
企业价值 保证系统可靠 保证会话连续 形成企业智能体经验资产和模型进化飞轮

三、它在 KodaX 生态中的位置

KodaX 负责产生底层执行 Trace，Space 负责端侧任务 Trace，AgentOS 负责组织级 Trace 的治理和资产化。

KodaX CLI 记录代码理解、工具调用、命令执行、文件修改、测试反馈等底层执行轨迹。
KodaX Space 记录端侧任务、个人电脑上下文、Skill 调用、Connector 接入和本地结果回传。
PAT Agent 负责 AgentOS 与 Space 之间的数据和任务通讯，并控制端侧 Trace 的出端边界。
ProjectAgent 记录项目目标、拆解策略、成员分工、成果审核和项目记忆沉淀。
OrgAgent 负责企业级治理、脱敏、审批、训练授权、数据集导出和反哺策略。
KodaX

懂执行过程

知道代码、工具、命令、文件、测试和错误修复路径，是最细粒度的执行 Trace 来源。

Space

懂员工端侧

知道个人任务、本地环境、桌面数据和端侧执行结果，是企业任务落到个人电脑后的 Trace 来源。

AgentOS

懂企业上下文

知道组织目标、项目关系、成员角色、审批权限和经验是否被认可，是 Trace 资产化的关键层。

四、端到端闭环

TraceOps 的目标是让每一次任务都可以变成下一代 Agent 的训练材料。

任务发生 项目、审批、数据请求、代码任务、Skill 调用或 Connector 调用开始。
全链路记录 AgentOS、PAT、Space、KodaX 按统一协议记录事件、上下文和产物。
治理提炼 脱敏、权限裁剪、去噪、质量评分，提取高价值成功链路和失败修复链路。
数据集生成 生成 SFT、工具调用、计划拆解、偏好、评测、路由和记忆数据集。
反哺模型 优化 KodaX 内核、ProjectAgent 拆解、PAT 路由、Skill 选择和企业 Agent 行为。
飞轮：任务越多 -> Trace 越多 -> 数据越好 -> Agent 越强 -> 企业越愿意使用 -> 产生更多 Trace。

五、系统架构

TraceOps 可以按六层建设，从采集到反哺，每一层都要面向企业级治理和未来训练使用。

1. 采集层

统一 Trace SDK / Event Bus

所有 Agent 和 Harness 都以统一事件格式写入 Trace。包括 ProjectAgent、PAT、OrgAgent、Space、KodaX、Skill、Connector。

关键能力：trace_id、session_id、event_id、span_id、parent_id、actor_id、agent_id。
2. 上下文层

Context Snapshot

记录任务发生时的项目、成员、权限、记忆、文档、代码仓库、工具可用性和企业策略版本。

关键能力：上下文快照、版本化、权限范围、引用而非复制敏感内容。
3. 存储层

Raw / Clean / Train 三层数据湖

原始 Trace 用于审计和回放，清洗 Trace 用于分析和提炼，训练 Trace 用于导出和模型优化。

关键能力：不可篡改原始记录、脱敏副本、训练授权副本。
4. 治理层

Policy / Redaction / Approval

判断哪些 Trace 可项目内查看、可进入企业记忆、可导出训练、必须脱敏、必须人工审批。

关键能力：数据分级、脱敏规则、保留周期、训练授权、审计。
5. 提炼层

Trace Distiller

从复杂原始链路中提取高价值样本，包括成功链路、失败修复、优秀计划、工具调用轨迹和人工偏好。

关键能力：质量评分、去噪、链路压缩、样本构造、人工校验。
6. 反哺层

Dataset / Eval / Fine-tune / Routing

导出训练集和评测集，优化 KodaX 内核、Agent 角色配置、Skill 市场排序和任务路由策略。

关键能力：JSONL、Parquet、OpenAI 格式、内部训练格式、评测基准。

六、核心数据模型

TraceOps 的数据模型应该同时服务回放、治理、训练和评测。

Trace

一次完整任务链路

从目标产生到结果确认的全局容器。它跨 Agent、跨 Space、跨 KodaX 执行过程。

Session

一次交互会话

用户与 Agent 的对话、确认、审批和反馈，可能属于某个 Trace 的一个阶段。

Event

一个可追踪事件

计划、工具调用、文件读取、消息转发、结果回传、审批、记忆入库等都应该被事件化。

七、事件分类

统一事件分类可以保证不同 Agent、工具和端侧执行过程能够被拼成一条完整链路。

context.loaded 加载项目、文档、记忆、代码仓库、连接器数据 AgentOS / Space 训练上下文选择与检索策略
plan.created 生成任务计划、步骤、节点和成员分工 ProjectAgent 训练复杂任务拆解能力
task.dispatched 将任务分发给成员 PAT 或 Space ProjectAgent / PAT 训练 Agent 路由和任务分配
tool.called 调用工具、Skill、Connector、命令或 API KodaX / Space 训练工具调用轨迹

八、三类 Agent 的职责

TraceOps 不是单个 Agent 的能力，而是 PAT、ProjectAgent、OrgAgent 分工协作的底层系统。

PAT Agent

采集和转运 Trace

  • 记录 AgentOS 与 Space 之间的数据/任务消息。
  • 标记哪些数据来自端侧，哪些只能摘要回传。
  • 为每次 Space 执行生成 trace_id 和路由记录。
  • 提示用户是否允许敏感 Trace 出端。
ProjectAgent

解释和评价 Trace

  • 记录项目目标、拆解依据和成员分工。
  • 关联所有成员 PAT 回传的执行结果。
  • 判断 Trace 是否完成项目目标。
  • 将高价值链路提炼为项目记忆候选。
OrgAgent

治理和资产化 Trace

  • 维护企业级 Trace 策略、脱敏规则和保留周期。
  • 审批 Trace 是否进入企业记忆或训练数据池。
  • 管理可导出的数据集和评测集。
  • 追踪 Trace 对模型和 Agent 能力的反哺效果。

九、Trace 治理

企业级 Trace 最大的难点不是采集，而是知道什么可以被使用、如何使用、被谁使用。

治理边界

必须先分级，再训练

  • L0 公开样本：无敏感信息，可进入通用训练和展示。
  • L1 企业内部：只在企业租户内使用，可进入企业私有训练。
  • L2 项目受限：只允许项目内回放和分析，不进入全局训练。
  • L3 端侧敏感：只允许摘要、指标或哈希出端。
  • L4 禁止训练：仅可审计，不可进入记忆、评测或训练。
审批策略

训练数据需要明确授权

  • 进入企业记忆前，需要项目负责人确认。
  • 进入训练数据池前，需要 OrgAgent 触发治理审批。
  • 涉及客户、合同、源码、数据库字段时，必须先脱敏。
  • 端侧文件默认不上传原文，只上传摘要、引用和证据哈希。
  • 训练导出需要记录导出人、用途、时间、数据版本。
治理动作 触发条件 负责人 输出结果
脱敏 Trace 包含姓名、客户、合同、代码、密钥、数据库字段 OrgAgent + 数据负责人 生成 clean_trace，并保留 redaction map
裁剪 Trace 中存在无关上下文、长日志、重复消息 Trace Distiller 生成可阅读、可训练的链路摘要
授权 Trace 准备进入企业记忆或训练池 项目负责人 / 管理员 设置 usage_scope 和 expires_at
保留 原始 Trace 超过企业保留周期 OrgAgent 归档、删除或只保留摘要

十、自蒸馏数据流水线

自蒸馏不是把所有 Trace 丢给模型，而是把高质量链路转化成明确任务类型的数据集。

Raw Trace 完整记录所有过程，包含噪声、失败、敏感字段和无关上下文。
Clean Trace 脱敏、去噪、压缩、结构化，保留决策、工具、结果和反馈信号。
Candidate 筛选成功链路、失败修复链路、负责人认可结果和高复用经验。
Dataset 构造 SFT、Tool-use、Planning、Preference、Evaluation 多类样本。
Model / Agent 训练、评测或调整 KodaX 内核、Agent 配置、Skill 路由和计划策略。
SFT 数据

学会高质量结果

从“用户目标 + 上下文 -> 被接受的最终产物”构造监督微调样本。

Tool-use 数据

学会调用工具

从“任务 -> 工具选择 -> 参数 -> 观察 -> 下一步”构造工具调用轨迹。

Planning 数据

学会拆解项目

从 ProjectAgent 的项目拆解、成员分工、节点依赖中学习长程任务计划。

Preference 数据

学会判断好坏

从负责人接受/驳回、人工修改、A/B 结果中构造偏好样本。

Repair 数据

学会修复失败

从失败、诊断、重试、修复成功链路中训练错误恢复能力。

Evaluation 数据

建立真实评测

把企业真实任务抽象成 benchmark，用于评估新模型、新 Skill 和新 Agent 配置。

十一、产品形态

TraceOps 可以在 AgentOS 内形成一组后台能力，不一定一开始暴露给普通员工，但需要服务管理者、数据负责人和模型团队。

Trace 看板

企业智能体运行数据总览

  • 今日 Trace 数、成功率、失败修复率、平均任务长度。
  • 按项目、Agent、Skill、Connector、员工、Space 节点聚合。
  • 可训练比例、待脱敏比例、待审批比例、训练贡献度。
Trace 回放

像时间线一样复盘任务

  • 展示用户目标、Agent 计划、工具调用、失败、修复和结果。
  • 支持按 Agent、工具、成员、文件、审批筛选。
  • 帮助项目负责人理解结果是怎么来的。
高价值候选池

把好链路挑出来

  • 自动识别完整成功链路、失败修复链路和人工认可结果。
  • 给每条 Trace 打训练价值、复用价值、风险等级。
  • 支持人工标注“好样本、差样本、禁止训练”。
数据集导出

让 Trace 变成训练材料

  • 按数据类型导出 JSONL、Parquet、OpenAI fine-tune 格式。
  • 导出前进行脱敏、采样、版本锁定和审批。
  • 记录导出目的、负责人、模型版本和使用范围。

任务完整度 有明确目标、计划、执行、结果和验收 只有碎片聊天或中途停止 判断是否可进入候选池
结果质量 被负责人接受，或被后续项目复用 结果被驳回、需要大量人工重写 构造 SFT 和偏好数据
执行复杂度 包含多步计划、工具调用、错误修复 单轮简单问答 识别长程 Agent 能力样本
治理风险 敏感信息少、脱敏成本低、授权明确 包含大量客户、源码、隐私或密钥 决定训练范围和审批方式

十四、与企业记忆库的关系

企业记忆库沉淀“可复用结论”，TraceOps 沉淀“结论是如何形成的”。

企业记忆库

组织经验的稳定表达

  • 项目复盘结论。
  • 最佳实践。
  • 业务规则。
  • 知识口径。
  • 可被问答和检索的经验。
TraceOps

组织经验的形成过程

  • 谁提出了目标。
  • Agent 如何拆解。
  • 工具如何执行。
  • 错误如何修复。
  • 结果如何被确认。

两者应该互相连接：高质量 Trace 可以提炼成企业记忆；企业记忆又会成为下一次 Trace 的上下文输入。 TraceOps 负责保留过程，企业记忆库负责沉淀结论。

十五、落地路线

TraceOps 不需要第一天就变成训练平台，应该先把记录和回放做扎实，再逐步治理、提炼和反哺。

阶段 建设目标 关键能力 验收标准
Phase 1 先留全 统一 trace_id、事件协议、KodaX/Space/AgentOS 基础采集 任意一次项目任务可以追溯完整链路
Phase 2 能看懂 Trace 回放、时间线、节点图、工具调用表、产物列表 项目负责人能复盘“结果怎么来的”
Phase 3 能治理 脱敏、数据分级、训练授权、审批、保留周期 Trace 是否可训练有明确状态和审批记录
Phase 4 能提炼 高价值 Trace 候选、质量评分、失败修复链路提取 能自动生成候选训练样本和企业记忆候选
Phase 5 能导出 JSONL、Parquet、OpenAI fine-tune、内部训练格式 数据集可版本化、可追溯、可审批导出
Phase 6 能反哺 模型评测、Agent 配置优化、Skill 排序、路由策略更新 新模型或新策略在真实评测集上持续提升

十六、MVP 版本建议

第一版不要做成庞大的训练平台，而是先做 AgentOS 的 Trace 记录、回放和候选池。

P0

Trace Viewer

在项目页支持查看一次任务的 Trace 时间线，包括 ProjectAgent 拆解、PAT 分发、Space 执行和结果回传。

P0

Trace ID 打通

AgentOS、PAT、Space、KodaX 使用同一 trace_id，保证一次任务跨系统可追踪。

P0

训练授权状态

每条 Trace 至少有“禁止训练、待审批、企业内可训练、公开可训练”四种状态。

P1

高价值候选

自动把成功完成、负责人确认、失败后修复成功的 Trace 标记为候选样本。

P1

基础脱敏

对姓名、手机号、邮箱、密钥、客户名、数据库字段、文件路径做基础识别和遮罩。

P1

JSONL 导出

支持将已授权 Trace 导出为基础 instruction 数据和 tool trajectory 数据。

十七、风险与边界

TraceOps 的价值很大，但不能牺牲企业安全和员工信任。

主要风险
  • 把敏感业务数据、客户数据或源码误导出训练。
  • Trace 太脏，直接训练会放大错误行为。
  • 只重视成功样本，忽略失败修复过程的价值。
  • 记录过度细节，导致员工对端侧 Agent 缺少信任。
  • 没有版本和血缘，训练后无法追溯数据来源。
设计原则
  • 默认最小采集，按场景逐步增加。
  • 端侧敏感数据默认不出端。
  • 训练数据必须经过治理状态机。
  • 原始 Trace、清洗 Trace、训练 Trace 严格分层。
  • 所有导出都可追溯、可撤回、可审计。

十八、战略价值总结

TraceOps 可以让 AgentOS 从“企业智能体管理系统”升级为“企业智能体经验资产操作系统”。

对 KodaX

让执行内核持续进化

真实 coding、工具调用、修复路径和测试反馈会反过来优化 KodaX Agent 内核。

对 Space

让端侧任务形成复利

每个员工电脑上的任务执行经验不再散落，而是可治理地回流到企业智能底座。

对 AgentOS

让管理系统变成数据飞轮

项目、组织、审批、记忆和训练全部被一条 Trace 资产链路串起来。

未来最强的企业 Agent，不一定来自最大的模型，而可能来自拥有最多真实任务 Trace、最强治理能力和最快自蒸馏闭环的系统。
