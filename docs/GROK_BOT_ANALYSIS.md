## 0. 一句话

**Grok Bot 是常驻的 AI 同事。** 每个 Bot 有固定岗位和自己的记忆；同一个用户的所有 Bot 共用一台云电脑，用户离线时也在干活。产品由 SpaceXAI（原 xAI）与 Cursor 一起推出，**跑在 Cursor 的平台上**。

xAI 把用户要理解的概念压到五个：**Bot、Chat、Prompt（→ Skill / Routine）、Memory、Tool**，外加 Bot 的产出物 Artifact。其余概念「等用户有理由关心时再出现」。

## 1. 整体架构层级

从上到下五层。Cursor 是底座，而不只是「旁边的另一套产品」。

```text
┌─ 1 交互层 ───────────────────────────────────────────────────────────────┐
│ ┌─────────────────────┐  ┌─────────────────────┐  ┌────────────────────┐ │
│ │     桌面 / Web      │  │     单聊、群聊      │  │    状态 / 预览     │ │
│ │      手机 App       │  │    最多 6 个 Bot    │  │      人工接管      │ │
│ └─────────────────────┘  └─────────────────────┘  └────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 2 Bot 层：每个 Bot 各自拥有 ────────────────────────────────────────────┐
│ ┌───────────────┐  ┌───────────────┐  ┌──────────────┐  ┌──────────────┐ │
│ │     身份      │  │     记忆      │  │   Routines   │  │   独立屏幕   │ │
│ │  名字、头像   │  │   对话历史    │  │   长期职责   │  │  可并行工作  │ │
│ │     岗位      │  └───────────────┘  └──────────────┘  └──────────────┘ │
│ └───────────────┘                                                        │
└──────────────────────────────────────────────────────────────────────────┘
                                     │ Bot 调用共享能力
                                     ▼
┌─ 3 账号层：所有 Bot 共享 ────────────────────────────────────────────────┐
│ ┌─────────────────────┐  ┌─────────────────────┐  ┌────────────────────┐ │
│ │       技能库        │  │     插件 / MCP      │  │    文件、浏览器    │ │
│ │       Skills        │  │       连接器        │  │  登录态、CLI 凭证  │ │
│ └─────────────────────┘  └─────────────────────┘  └────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────┘
                                     │ 在云上执行
                                     ▼
┌─ 4 执行层 ───────────────────────────────────────────────────────────────┐
│ ┌─────────────────────────────────┐  ┌─────────────────────────────────┐ │
│ │           持久云电脑            │  │       Cursor Cloud Agents       │ │
│ │       每用户一台微虚拟机        │  │            编码任务             │ │
│ │         用户离线也在跑          │  │      每个 agent 一台虚拟机      │ │
│ └─────────────────────────────────┘  └─────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────┘
                                     │ 全部跑在
                                     ▼
┌─ 5 Cursor 平台底座 ──────────────────────────────────────────────────────┐
│ ┌───────────────┐  ┌───────────────┐  ┌──────────────┐  ┌──────────────┐ │
│ │  账号 / 鉴权  │  │    连接器     │  │   模型路由   │  │     计费     │ │
│ │   管理后台    │  │   凭证存放    │  │  用户不能选  │  │    用量池    │ │
│ └───────────────┘  └───────────────┘  └──────────────┘  └──────────────┘ │
└──────────────────────────────────────────────────────────────────────────┘

┌─ 横切 ───────────────────────────────────────────────────────────────────┐
│      Auto Review 审批 / 隐私模式 / 管理员策略：作用于第 2 到第 4 层      │
└──────────────────────────────────────────────────────────────────────────┘
```

| 层 | 关键事实 |
|---|---|
| 交互层 | 对话、系统事件、交互卡片、可视化共用一条时间线；回复的形式也是答案的一部分（例如直接给一张邮件草稿卡） |
| Bot 层 | Bot 是主对象，不是对话。「明天回来，还是同一个 Bot。」每个账号大约 50 个 Bot |
| 账号层 | 工具和技能放在账号级，因为很多 Bot 都要用 |
| 执行层 | 云电脑上有浏览器、文件系统和终端；编码可以委派给 Cursor Cloud Agents |
| Cursor 底座 | 官方说 Grok Bot 运行在 Cursor 的云上，用 Cursor 账号登录，在 Cursor 后台管理 |

> 未公开：Bot 的编排逻辑是否直接复用 Cursor 的 agent harness。

## 2. 什么共享、什么归 Bot

这是 Grok Bot 最核心的一条设计原则：**能力可以广泛共享，上下文留给需要它的岗位。**

```text
┌─ 账号级：共享 ───────────────────────────────────────────────────────────┐
│ ┌───────────┐  ┌───────────┐  ┌───────────┐  ┌───────────┐  ┌──────────┐ │
│ │ 用户事实  │  │   工具    │  │   技能    │  │   插件    │  │  云电脑  │ │
│ │ 姓名 时区 │  │   Tools   │  │  Skills   │  │    MCP    │  │ 文件凭证 │ │
│ └───────────┘  └───────────┘  └───────────┘  └───────────┘  └──────────┘ │
└──────────────────────────────────────────────────────────────────────────┘
                                     │ 所有 Bot 都能用
                                     ▼
┌─ Bot 级：各自拥有，记忆互不相通 ─────────────────────────────────────────┐
│ ┌─ 法务 Bot ─────────┐   ┌─ 财务 Bot ─────────┐   ┌─ 调研 Bot ─────────┐ │
│ │ 身份、岗位         │   │ 身份、岗位         │   │ 身份、岗位         │ │
│ │ 记忆               │   │ 记忆               │   │ 记忆               │ │
│ │ Routines           │   │ Routines           │   │ Routines           │ │
│ │ 自己的屏幕         │   │ 自己的屏幕         │   │ 自己的屏幕         │ │
│ └────────────────────┘   └────────────────────┘   └────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────┘
                                     │ 几个 Bot 拉进同一个群
                                     ▼
┌─ 群聊 ───────────────────────────────────────────────────────────────────┐
│ 共享：这个项目的上下文                                                   │
│ 不共享：每个成员 Bot 仍保留自己的记忆                                    │
└──────────────────────────────────────────────────────────────────────────┘
```

为什么记忆不共享：法务 Bot 需要纠纷历史，财务 Bot 需要多年账目。把两份历史合成一份大记忆，反而更难给每个 Bot 找到和它工作相关的信息。

## 3. 一个 Bot 的内部结构

```text
┌─ 触发 ───────────────────────────────────────────────────────────────────┐
│            用户消息 / 群聊消息 / Routine 定时或事件 / Webhook            │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 一个 Bot ───────────────────────────────────────────────────────────────┐
│ ┌────────────────────┐   ┌────────────────────┐   ┌────────────────────┐ │
│ │        身份        │   │        记忆        │   │      Routines      │ │
│ │   名字 头像 岗位   │   │        偏好        │   │    这个 Bot 的     │ │
│ │     边界：例如     │   │    过往工作摘要    │   │      长期职责      │ │
│ │    不得对外发送    │   │      对话历史      │   │                    │ │
│ └────────────────────┘   └────────────────────┘   └────────────────────┘ │
│                                    │ 装进上下文                          │
│                                    ▼                                     │
│                 ┌──────────────────────────────────────┐                 │
│                 │               推理循环               │                 │
│                 │          模型由平台自动路由          │                 │
│                 └──────────────────────────────────────┘                 │
└──────────────────────────────────────────────────────────────────────────┘
                                     │ 按需调用账号层能力
         ┌──────────────────┬────────┴─────────┬──────────────────┐
         ▼                  ▼                  ▼                  ▼
 ┌───────────────┐  ┌───────────────┐  ┌───────────────┐  ┌───────────────┐
 │ 1 连接器优先  │  │ 2 终端 / 文件 │  │ 3 浏览器操作  │  │  4 委派编码   │
 │  插件 / MCP   │  │  仓库、命令   │  │ computer-use  │  │  Cloud Agent  │
 │ 拿不到 token  │  │               │  │ 没连接器才用  │  │ 另一台虚拟机  │
 └───────────────┘  └───────────────┘  └───────────────┘  └───────────────┘
         └──────────────────┴────────┬─────────┴──────────────────┘
                                     │
                                     ▼
┌──────────────────────────────────────────────────────────────────────────┐
│                     产出：回复 / 卡片 / 文件 / 代码                      │
│                         同时写回这个 Bot 的记忆                          │
└──────────────────────────────────────────────────────────────────────────┘
```

调用能力时有固定的优先顺序：**有连接器就走连接器，没有才用浏览器操作。** 连接器更稳定，而且 Bot 拿不到 OAuth token。

## 4. 一个 Bot 怎么构建出来

官方没有固定的「创建向导」。Bot 是在使用中一步步长出来的：先建岗位，跑通一次任务，再把它变成技能和例行职责。

```text
┌─ 1 用户 > Bot ───────────────────────────────────────────────────────────┐
│ 新建 Bot：起名、选头像、写岗位                                           │
│ 官方建议岗位要窄：窄岗位积累的上下文更有用                               │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 2 用户 > Bot ───────────────────────────────────────────────────────────┐
│ 交代一个一次性任务                                                       │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 3 Bot ──────────────────────────────────────────────────────────────────┐
│ 用已装的插件 / 连接器，或云电脑上的终端、文件、浏览器                    │
│ 把结果交给用户                                                           │
└──────────────────────────────────────────────────────────────────────────┘
                                     │ 沉淀成技能
                   ┌─────────────────┴──────────────────┐
                   ▼                                    ▼
  ┌─ 方式 A ────────────────────────┐  ┌─ 方式 B ────────────────────────┐
  │ 这次做法值得复用                │  │ 用户想直接演示                  │
  │                                 │  │                                 │
  │ 用户：存为技能                  │  │ Teach a task：演示一遍          │
  │ 写入账号技能库                  │  │ 浏览器操作（10 分钟内）         │
  │ 所有 Bot 都能用                 │  │ Bot 起草技能，等用户审阅        │
  └─────────────────────────────────┘  └─────────────────────────────────┘
                   └─────────────────┬──────────────────┘
                                     │
                                     ▼
┌─ 4 用户 > Bot ───────────────────────────────────────────────────────────┐
│ 补上失败处理和审批边界，先用安全输入试跑                                 │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 5 用户 > Bot ───────────────────────────────────────────────────────────┐
│ 用户：每天早上给我一份简报                                               │
│ Bot：已创建 Routine「Morning Briefing」                                  │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌──────────────────────────────────────────────────────────────────────────┐
│                 从此 Bot 有了长期职责，不再只是被叫才动                  │
└──────────────────────────────────────────────────────────────────────────┘
```

技能草稿要补上失败处理和审批边界，先在安全输入上试跑，再交给 Routine 自动执行。

## 5. 一次任务怎么执行

从上往下读：先定目标和边界，再按任务类型走四条路径之一，最后写回记忆。

```text
┌─ 1 用户 > Bot ───────────────────────────────────────────────────────────┐
│ 交代目标，同时写清边界                                                   │
│ 例：别发邮件，别改 CRM                                                   │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 2 Bot ──────────────────────────────────────────────────────────────────┐
│ 加载身份、记忆、可用技能，决定每一步用什么能力                           │
└──────────────────────────────────────────────────────────────────────────┘
                                     │ 按任务类型分流
        ┌───────────────────┬────────┴──────────┬──────────────────┐
        ▼                   ▼                   ▼                  ▼
┌─ A ────────────┐  ┌─ B ────────────┐  ┌─ C ───────────┐  ┌─ D ───────────┐
│ 有连接器       │  │ 文件/仓库/命令 │  │ 无连接器      │  │ 编码任务      │
│                │  │                │  │               │  │               │
│ Auto Review    │  │ 在云电脑的     │  │ computer-use  │  │ Auto Review   │
│ 先审           │  │ 终端里执行     │  │ 操作浏览器    │  │ 先审          │
│                │  │                │  │               │  │ 用户确认      │
│ 调用连接器     │  │                │  │ 遇到密码、    │  │ 验收标准      │
│ 凭证由平台托管 │  │                │  │ 验证码、付款  │  │               │
│                │  │                │  │ 转给用户接管  │  │ Cloud Agent   │
│                │  │                │  │               │  │ 开 PR，走评审 │
└────────────────┘  └────────────────┘  └───────────────┘  └───────────────┘
        └───────────────────┴────────┬──────────┴──────────────────┘
                                     │
                                     ▼
┌─ 3 Bot ──────────────────────────────────────────────────────────────────┐
│ 写回这个 Bot 的记忆                                                      │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 4 Bot > 用户 ───────────────────────────────────────────────────────────┐
│ 回复或卡片，状态是：完成 / 等待中 / 失败                                 │
└──────────────────────────────────────────────────────────────────────────┘
```

几个容易讲错的点：

- **批准委派不等于批准合并。** Cloud Agent 返回的代码还要走正常代码评审。
- **「停止」不会撤销已经做完的动作**，所以要在开头写清楚边界，而不是指望事后拦。
- **关掉电脑任务也不会停**，因为它跑在云电脑上。

## 6. Routine：没人叫也会干活

Routine 让 Bot 从「被叫才动」变成「有长期职责」。xAI 一开始把它当作次要配置，后来移到了 Bot 的主界面。

```text
┌─ 触发源 ─────────────────────────────────────────────────────────────────┐
│ 定时：每天、每周                                                         │
│ 事件：GitHub、Slack、Linear 等                                           │
│ Webhook：POST + Bearer key                                               │
│ 注意：Webhook 返回 200 只代表已开始，不代表已完成                        │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ Routine ────────────────────────────────────────────────────────────────┐
│ 只属于一个 Bot，带着这条 Routine 的工作说明唤醒它                        │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ Bot ────────────────────────────────────────────────────────────────────┐
│ 按技能执行：云电脑、连接器                                               │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ Bot ────────────────────────────────────────────────────────────────────┐
│ 运行记录写进 Bot 的对话时间线                                            │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                  ┌──────────────────┴─────────────────┐
                  ▼                                    ▼
 ┌─────────────────────────────────┐  ┌──────────────────────────────────┐
 │           需要人判断            │  │             正常完成             │
 │       侧栏提示：等你确认        │  │ 结果留在对话里，下次打开就能看到 │
 └─────────────────────────────────┘  └──────────────────────────────────┘
```

| 规则 | 说明 |
|---|---|
| 归属 | 一条 Routine 只属于一个 Bot；删掉 Bot，它的 Routine 也会被删除 |
| 数量 | 每个 Bot 最多 50 条 Routine，每条保留最近 20 次运行记录 |
| 频率 | Webhook 触发每条每小时 200 次，全部 Routine 合计每小时 300 次（来自第三方手册） |

## 7. 群聊与协调

Grok Bot 刻意**没有做看板和任务分配面板**，因为那会给用户增加管理工作。协调交给 Bot 自己做，只在需要判断时把用户拉进来。

```text
┌─ 一个群聊（最多约 6 个 Bot） ────────────────────────────────────────────┐
│     ┌──────────┐  ┌────────────────┐  ┌────────────┐  ┌────────────┐     │
│     │   用户   │  │    协调 Bot    │  │  调研 Bot  │  │  写作 Bot  │     │
│     └──────────┘  │ Chief of Staff │  └────────────┘  └────────────┘     │
│                   └────────────────┘                                     │
│                                                                          │
│            ┌────────────────────────────────────────────────┐            │
│            │        共享文件：Bot 之间交接资料的地方        │            │
│            └────────────────────────────────────────────────┘            │
└──────────────────────────────────────────────────────────────────────────┘
                                     │ 群里开始干活
                                     ▼
┌─ 1 用户 > 协调 Bot ──────────────────────────────────────────────────────┐
│ 周五前出一份竞品分析                                                     │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 2 协调 Bot > 调研 Bot ──────────────────────────────────────────────────┐
│ 你先收集资料                                                             │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 3 调研 Bot > 共享文件 ──────────────────────────────────────────────────┐
│ 资料写进共享文件，交接回协调 Bot                                         │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 4 协调 Bot > 写作 Bot ──────────────────────────────────────────────────┐
│ 根据资料写报告                                                           │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 5 写作 Bot > 协调 Bot ──────────────────────────────────────────────────┐
│ 读共享文件，交初稿                                                       │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 6 协调 Bot > 用户 ──────────────────────────────────────────────────────┐
│ 需要你拍板：结论这样写行吗？                                             │
└──────────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────────┐
│      没有看板和任务分配面板：协调交给 Bot，只在需要判断时拉用户进来      │
└──────────────────────────────────────────────────────────────────────────┘
```

- 群聊最多大约 6 个 Bot。
- Bot 之间的信息只通过四条路传递：**群聊消息、交接、共享文件、共享浏览器会话。**

## 8. Bot 的状态

状态用头像的动态表情表达，不单独加状态角标。用户研究发现，大家想看步骤细节，主要是为了确认「Bot 还在干活」。

```text
     ┌──────────────────────── 下一次触发 ───────────────────────┐
     ▼                                                           │
┌──────────┐        ┌──────────┐        ┌──────────┐        ┌──────────┐
│   空闲   │ ─────> │   思考   │ ─────> │  工作中  │ ─────> │   完成   │
└──────────┘        └──────────┘        └──────────┘        └──────────┘
                                             │
                                 ┌───────────┴─────────┐
                                 ▼                     ▼
                         ┌────────────────┐  ┌────────────────────┐
                         │      等待      │  │        受阻        │
                         │  需要用户确认  │  │ 登录、验证码、报错 │
                         │   确认后继续   │  │   用户接管后交还   │
                         └────────────────┘  └────────────────────┘

等待、受阻处理完，都回到「工作中」
```

用户看 Bot 的电脑有三档：

| 档位 | 表现 |
|---|---|
| 状态 | 电脑在工作时，标题栏图标变紫 |
| 预览 | 侧边固定面板，边聊边看它在做什么 |
| 接管 | 全屏打开 Bot 的电脑，亲自操作，做完再交还 |

官方特意没让「电脑」太显眼，因为那会把用户推向「盯着它干活」。电脑始终是 Bot 的工作区。

## 9. 安全边界

```text
┌─ 团队：在 Cursor 后台管理 ───────────────────────────────────────────────┐
│ ┌─ 用户 A 的云电脑 ─────────────────┐          ┌─ 用户 B 的云电脑 ─────┐ │
│ │ ┌───────┐  ┌───────┐  ┌───────┐   │          │      ┌───────┐        │ │
│ │ │ Bot 1 │  │ Bot 2 │  │ Bot 3 │   │          │      │ Bot 1 │        │ │
│ │ └───────┘  └───────┘  └───────┘   │  硬件级  │      └───────┘        │ │
│ │     └──────────┼──────────┘       │  隔离    │                       │ │
│ │                │                  │  <───>   │          │            │ │
│ │                ▼                  │          │          ▼            │ │
│ │ ┌─────────────────────────────┐   │          │ ┌─────────────────┐   │ │
│ │ │         共享：文件          │   │          │ │   共享：文件    │   │ │
│ │ │        浏览器登录态         │   │          │ │  浏览器登录态   │   │ │
│ │ │          CLI 凭证           │   │          │ │    CLI 凭证     │   │ │
│ │ └─────────────────────────────┘   │          │ └─────────────────┘   │ │
│ └───────────────────────────────────┘          └───────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────┘
                                     │ 用户 A 的 Bot 委派编码
                                     ▼
┌──────────────────────────────────────────────────────────────────────────┐
│                 Cloud Agents：每个 agent 一台独立虚拟机                  │
└──────────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────────┐
│  同一用户的 Bot 之间不隔离：屏幕只是工作面，删掉 Bot 后文件和登录态还在  │
└──────────────────────────────────────────────────────────────────────────┘
```

| 边界 | 是否隔离 |
|---|---|
| 用户和用户之间 | ✅ 每人一台微虚拟机，硬件级隔离 |
| 同一用户的 Bot 之间 | ❌ 官方明确说：不要把不同 Bot 当作安全边界 |
| 屏幕 | ❌ 屏幕只是工作面，不是隔离 |
| 删除 Bot | 共享的文件和登录态仍然留在电脑上 |
| 连接器策略 | 团队允许的连接器，对成员的每个 Bot 都可用 |
| 封禁插件 | 不会封住该服务的网站，要靠企业版网络管控 |
| 密钥 | 不该出现在聊天里；安全密钥请求会遮蔽，模型看不到 |

## 10. 对照 AgentOS

| Grok Bot | AgentOS | 处理方式 |
|---|---|---|
| Cursor 平台底座 | KodaX runtime | 同构：底座提供执行内核、账号、模型和工具 |
| Bot 是主对象，记忆按 Bot 隔离 | 智能体是基本单位 | 直接借鉴 |
| 群聊、交接、协调 Bot | 智能体群 / 专家团 | 直接借鉴 |
| 技能和连接器账号内全部共享 | SkillHub / MCPHub，按智能体安装和授权 | **我们的差异点**：加一层授权和治理 |
| 同一用户的 Bot 之间不隔离 | 企业场景需要按智能体或部门隔离凭证 | **不照搬** |
| Routine | v0.3 文档里还比较弱 | 建议补上 |
| 不做看板，由 Bot 协调 | 首页（个人工作台 + 企业推荐）和市场 | 有意不同：企业需要门面和人才市场 |
| 无 | 沉淀为专家 → 企业市场 | 我们独有 |
