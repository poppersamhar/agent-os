# 前端原型功能清单（v0.3）

> 用途：对照 [README](../README.md) 和 [AgentOS 结构解析](AGENTOS_STRUCTURE.md)，记录原型功能的需求、实现进度和演示入口。
> 日期：2026-11-12。全部用 mock 数据实现，不接模型、不接真实 MCP、不做后端。
> 优先级：**P0** 讲清产品差异必须有；**P1** 让流程完整；**P2** 锦上添花。

## 实现进度

F-01 至 F-17 已接入 v0.3 原型。页面使用模拟数据，操作和审批结果保存在当前浏览器。Routine 支持配置触发条件和手动模拟运行。

| 演示入口 | 可体验的流程 |
|---|---|
| 人员查询 | 填入示例、脱敏查询、异常分析、审批后查看完整信息、查询留痕 |
| 首页、通知、连接器管理 | 审批申请、查看能力健康和敏感操作、按智能体撤销授权 |
| 风险跟进专家、竞品调研专家、品牌专家团 | 处理风险、运行 Routine、打开成果预览、从工作区下载样例 |
| 新建智能体、群成员、Agent Market | 重复招募、逐项授权、群内招募、沉淀预览、发布审批和版本更新 |

| 设计里的概念 | 原型现状 |

## 一、面板（重点）

### F-01 操作型 Widget：查询表单 · P0

**为什么**：这是我们和 Grok Bot、Claude Dashboards 最大的区别，也是 B 端场景真正需要的。

**要做**：
- 新增 Widget 类型 `query-form`：若干输入项 + 「查询」按钮 + 结果区。
- 新增一个示例智能体「人员查询」，装一个 mock 连接器「人员信息库」，它声明提供 `query-form`。
- 表单字段：身份证号（格式校验）、查询事由（必填）。
- 结果默认脱敏展示，例如姓名「张*」、身份证「3301**********1234」，提供「查看完整信息」按钮（需审批，见 F-05）。

**mock 数据**：5～8 条人员记录，含「无记录」「有记录」两种结果；输入不存在的身份证号返回「未查到」。

**验收**：在面板里输入身份证号和事由，点查询后 1 秒内出结果；事由为空时不能提交。

### F-02 操作型 Widget 的两种走法 · P0

**要做**：Widget 在 Spec 里声明 `action: 'direct' | 'agent'`。

| 走法 | 前端表现 |
|---|---|
| `direct` 直接调用 | 结果直接出现在面板；左侧对话插入一条系统记录：「你在面板查询了 3301…1234，事由：××」 |
| `agent` 交给智能体 | 提交内容变成一条结构化的用户消息发到左侧对话，智能体「思考」后回复，面板同步更新 |

示例：「人员查询」的查询表单用 `direct`；再加一个「异常分析」表单用 `agent`，输入身份证号后由智能体给出分析。

**验收**：两种走法的结果都出现在对话时间线里；刷新后仍在。

### F-03 表格 Widget 带操作按钮 · P1

**要做**：新增 `action-table`：每行带「处理 / 忽略 / 交给智能体」等按钮，点击后行状态变化，并写一条记录进对话。

**示例**：「风险跟进专家」的风险清单；「研发协作专家」的 PR 列表（已有 `repo` Widget，可以升级成带「请求评审」按钮）。

### F-04 每个 Widget 写明来源和刷新时间，能直接追问 · P0

**为什么**：借鉴 Claude Dashboards，让面板可信、可追溯。

**要做**：
- Widget 标题右侧显示来源标签（已有部分）和「更新于 10:24」。
- 悬停时出现「问问它」按钮：点击后在左侧输入框预填「解释一下『本周要点』里的数字」。
- Widget 菜单（`…`）：刷新、查看数据来源（技能或连接器名称、调用的工具）。

### F-05 面板操作的治理：事由、脱敏、审批、审计 · P0

**要做**：
- 敏感字段默认脱敏；点「查看完整信息」弹出审批卡（见 F-12），批准后才显示。
- 新增 `audit` Widget「查询记录」：时间、操作人、查询对象（脱敏）、事由、结果。
- 首页（企业效能管理智能体）能汇总所有智能体的敏感操作记录（见 F-08）。

**验收**：每次查询都在「查询记录」里留一条；记录不能在前端删除。

### F-06 成果预览 Widget · P1

**为什么**：做 PPT、文档、网页的智能体，面板应该直接展示成果，而不只是文件名。

**要做**：新增 `artifact-preview`：点「最近成果」里的文件，在面板里打开预览。PPT 支持翻页，文档显示正文，网页用缩略图。用 2～3 份内置样例即可。

### F-07 面板模板与随能力变化的提示 · P1

**要做**：
- 内置 4 个面板模板：调研类、内容产出类、查询类、运营监控类。新建智能体或招募专家时按类型套用。
- 智能体装上新技能或连接器后，面板顶部出现一次性提示：「装上了『网页调研』，面板多了『资料来源』」，可以撤销。
- 在对话里说「把运行记录放到最上面」，面板调整顺序（用关键词匹配模拟）。

### F-08 首页的治理面板 · P0

**为什么**：README 里说「治理是一等公民，由企业效能管理智能体统一查看」，现在首页还看不出来。

**要做**：在首页增加 3 个 Widget：

| Widget | 内容 |
|---|---|
| 待我审批 | 发布申请、授权申请、敏感操作审批，可以直接通过或退回 |
| 能力健康 | 技能失败率排行、连接器停用或凭证即将过期 |
| 敏感操作 | 最近的查询记录汇总，按智能体筛选 |

## 二、智能体

### F-09 Routine · P0

**要做**：
- 新增 `routines` Widget：列出这个智能体的长期职责，包括触发方式（每天 9:00 / 飞书新消息 / GitHub 新 PR）、上次运行时间和结果、开关。
- 在对话里说「每天早上给我一份简报」，智能体回复「已创建 Routine：每日简报」，Widget 里多一条。
- 「运行一次」按钮：模拟运行，结果写进对话，「最近成果」多一个文件。

**mock 数据**：给「竞品调研专家」「数据巡检专家」各预置 1～2 条 Routine。

### F-10 托管工作区 · P1

**要做**：新增 `workspace` Widget：按文件夹列出这个智能体的文件（产物、上传的资料、运行日志），显示大小和时间，可以预览和下载样例文件。说明文字：「只有这个智能体能访问」。

### F-11 每个智能体的授权清单 · P0

**为什么**：「按智能体授权」是我们和 Grok Bot 的核心差异，原型里完全看不到。

**要做**：
- 智能体面板里新增「能力与授权」：已授权的技能和连接器、授权人、到期时间。
- 智能体需要一个没授权的连接器时，对话里出现申请卡：「需要『人员信息库』的只读权限，申请理由：…」，点「提交申请」后通知中心出现审批。
- 连接器管理页：每个连接器显示「已授权给哪些智能体」，可以撤销。

### F-12 对话里的审批卡 · P0

**要做**：新增消息类型「审批卡」：动作描述、影响范围、通过或拒绝按钮，过期时间（例如 10 分钟）。用于对外发送、删除、查看完整敏感信息、申请授权。批准或拒绝后，卡片变成结果状态，并写入审计记录。

**示例**：让「会议纪要专家」把纪要发到群里时，先出审批卡。

### F-13 执行过程可见 · P2

**要做**：智能体回复上方可展开「执行步骤」：每一步用了哪条路径（连接器 / 临时沙箱 / KodaX CLI / KodaX Space）、调用了什么、耗时。用于讲清「执行层不做虚拟机」的设计。

## 三、招募与沉淀

### F-14 招募专家 = 新建实例 · P0

**现状问题**：同一个专家只能添加一次（已添加后显示「已添加」），和「招募就是新建实例」的设计不一致。

**要做**：
- 新建弹窗分成两个 Tab：「从空白开始」「招募专家」。
- 同一个专家可以招募多次，每次生成新实例，默认名「竞品调研专家 2」，可以改名。
- 招募时有一步「授权连接器」：列出专家需要的连接器，用户逐个确认授权，跳过的显示为「待授权」。
- 新实例的对话开场说明：「我是从『竞品调研专家』招募来的，记忆从空开始」。

### F-15 把专家招募进智能体群 · P1

**要做**：在智能体群的「成员」Widget 里加「招募专家」，从专家库选择后成为群成员（新实例）。

### F-16 沉淀预览 · P0

**要做**：点「沉淀为专家」后，弹窗分两栏：

| 留下（定义） | 去掉（记忆和环境） |
|---|---|
| 身份、提示词 | 记忆 12 条 |
| 技能、连接器清单 | 工作区文件 8 个 |
| 面板模板 | 凭证授权 2 个 |
| Routine 模板（可勾选） | 运行记录 |

底部是「同时提交发布到企业市场」。如果提示词里检测到疑似敏感信息（手机号、身份证号），给出警告，要求先删掉。

### F-17 市场的发布与版本 · P2

**要做**：「我的」来源下能看到自己提交的条目和审批状态；条目详情显示版本历史；已招募的实例在专家有新版本时提示「可更新定义，不影响记忆」。

## 建议的开发顺序

1. **第一批（讲清差异）**：F-01、F-02、F-05、F-12，一起做出「人员查询」这个完整示例；再做 F-11、F-14、F-16。
2. **第二批（流程完整）**：F-04、F-08、F-09、F-03、F-06。
3. **第三批**：F-07、F-10、F-15、F-13、F-17。

第一批做完，就能完整演示：**招募一个查询专家 → 授权连接器 → 在面板里查询 → 敏感信息审批 → 留下审计记录 → 沉淀成专家发布**。这条线覆盖了 README 里六个关键设计决策中的五个。
