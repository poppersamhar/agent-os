# AgentOS 产品设计 v0.3 · Bot 化

> 状态：设计定稿（前端原型阶段）｜日期：2026-11-10

---

## 0. 对外名称与核心概念（面向企业用户）

**智能体是基本单位**：每个页面、每段对话都是一个智能体。用户新建的是智能体；用得顺、值得复用时，可以把它**沉淀**为专家或专家团。专家、专家团是成熟的产物，但仍然是智能体。代码、数据结构和内部文档里沿用 bot / skill / mcp。

| 对外名称 | 内部概念 | 说明 |
|---|---|---|
| 智能体 | Bot（kind: bot，未沉淀） | 用户新建，完成任务或项目；在工作中自主添加、移除技能和连接器 |
| 智能体群 | Bot 群聊（kind: group，未沉淀） | 多个智能体协作 |
| 专家 | 已沉淀的 Bot（matured） | 成熟、可复用，可发布到企业市场（需审批） |
| 专家团 | 已沉淀的群聊（matured） | 同上 |
| 企业效能管理智能体 | 主 Bot（kind: main） | 首页，汇总全部智能体，是治理入口 |
| 专家管理 / 技能管理 / 连接器管理 | 系统 Bot（kind: system） | 也是智能体：左边对话，右边是管理面板；可以在对话里新增、修改智能体、技能、连接器 |
| 技能 | Skill | 智能体「会什么」 |
| 连接器 | MCP | 智能体能「连到哪些系统」；面向第三方接入时仍写 MCP |
| 工作台 | 仪表盘（Dashboard） | |
| 市场 | Agent Market | 上架的是专家、专家团、技能、连接器 |

**系统智能体的头像**：企业效能管理智能体与三个管理智能体各有一个专用形状，靠形状本身区分，不加角标——首页是圆角六边形（呼应 Agent OS Logo），专家管理是三个脑袋连成的团队，技能管理是四角星芒，连接器管理是带两根插脚的插头。这四种形状用户新建时选不到，自动分配也不会分到。

**沉淀**：在智能体工作台右上角点「沉淀为专家」（智能体群为「沉淀为专家团」），可勾选「同时提交发布到企业市场」，提交后通知中心出现审批进度。

以下章节为内部设计，沿用 Bot / Skill / MCP 的写法。

## 1. 产品判断

### 1.1 什么对我们最重要

AgentOS 与其他 Agent 产品的区别，不在于「能聊天、能出成果」——这已是各家标配——而在于 **能力层**：

- **AgentHub**：Bot 与 Bot 群聊（专家团）的创建、管理与治理
- **SkillHub**：可复用的工作方法，协助用户把一次成功的做法沉淀为 Skill
- **MCPHub**：接入外部系统的服务，协助用户创建、接入并统一管理 MCP

核心能力是两件事：**协助用户创建 Skill 与 MCP 服务**，以及 **统一管理和治理这些能力**（版本、负责人、授权、凭证、调用、失败率、依赖关系）。

### 1.2 借鉴 Grok Bot：Bot 是唯一的基本单元

不再把工作拆成「项目 / 会话 / 任务」多个容器：

- **一个对话就是一个 Bot**。Bot 不区分 session，对话历史与记忆都属于这个 Bot。
- **Bot 随能力生长**。为某件事构建的 Bot（如调研 Bot）会带着它需要的 Skill、MCP 和 prompt；能力增加，Bot 的工作台随之改变。
- **Bot 本身就是记忆系统**。Bot 知道什么、做过什么，都沉淀在 Bot 上，并可查看、修正、删除。

参考：xAI《Designing Grok Bot》的分层——Skill / 工具放在账号级共享，记忆与 Routine 属于 Bot，群聊提供共享上下文而每个 Bot 保留各自记忆。

## 2. 对象模型

```
账号/组织级（共享）               Bot 级（各自拥有）              群聊
─────────────────               ────────────────              ─────
Skill   ──安装到──▶            身份 · prompt · 模型           成员 Bot 列表
MCP     ──授权给──▶            已装 Skill / MCP               共享上下文
Widget 组件库                   记忆（可查看/编辑）             每个成员保留自身记忆
                                对话流（无 session）
                                Dashboard Spec（由能力生成）
                                运行记录 · 状态
```

| 对象 | 关键字段 |
|---|---|
| **Bot** | 名称、角色 prompt、模型、已装 Skill、已装 MCP、记忆、消息、运行记录、状态（空闲 / 工作中）、Dashboard Spec |
| **群聊 Bot** | 同 Bot，另有成员 Bot 列表；仪表盘汇总成员 |
| **主 Bot** | 唯一；仪表盘汇总全部 Bot；同时是治理入口（可直接问「哪些 Skill 这周失败最多」） |
| **Skill** | 名称、说明、版本、负责人、分类、提供的 Widget、调用次数、失败率、被哪些 Bot 使用 |
| **MCP** | 名称、类型（飞书 / GitHub / 数据库 / 自定义）、端点、凭证托管方式、工具列表、状态、提供的 Widget、被哪些 Bot 使用 |
| **Widget** | 组件库中的固定渲染单元（待处理、运行记录、列表、趋势、指标等） |

## 3. 界面结构

```
┌──────────────────────────────────────────────────────────────┐
│ ● Agent OS                                              (头像) │
├───────────────────┬──────────────────────────────────────────┤
│  左栏：当前 Bot     │  右栏：当前 Bot 的仪表盘                   │
│  的对话流（深色）   │  （由 Bot 的 prompt + Skill + MCP 生成）   │
│  · 发送人 / 来源    │                                          │
│  · 文件卡片         │                                          │
│  · 对话导航         │                                          │
│  [收起]            │                                          │
├───────────────────┴──────────────────────────────────────────┤
│ [当前 Bot ■]  │ (+)  [Bot A] [Bot B] [Bot C] …   ← Bot 栏      │
│ [收起的对话]  (H)  [ 告诉我你想做什么任务…  ● ]  [Bot管理][Skill管理][MCP管理] │
└──────────────────────────────────────────────────────────────┘
```

### 3.1 输入行（最下）
- **H**：主 Bot。点击后面板切到主 Bot（全局仪表盘 + 主 Bot 对话）。
- **输入框**：发给当前 Bot；多行时自动增高。
- **三个 Hub 入口**：Bot 管理、Skill 管理、MCP 管理。打开后占据面板区域。

### 3.2 Bot 栏（输入行上方）
- 最左的黑色胶囊 = **当前正在对话的 Bot**。
- 「+」新建 Bot（或群聊）。
- 其余 Bot 只做一种区分：**是否为当前 Bot**。不按颜色深浅表示时间或状态。
- Bot 正在执行任务时，显示轻微动效和小角标「1」（进行中的任务数）。
- 用户一发送 query，当前 Bot 移到第一位。

### 3.3 面板（上方，左右两栏）
- **左栏 = 当前 Bot 的对话框**。可以收起；收起后变成 Bot 栏左下的深色小卡片，仪表盘占满宽度。
- **右栏 = 当前 Bot 的仪表盘**。

## 4. 仪表盘生成（Bot 构建工程的核心）

**原则：Bot 不生成代码，只生成声明式的 Dashboard Spec（JSON），由固定的 Widget 组件库渲染。** 保证视觉统一、可治理、可版本化。

1. **能力声明 Widget**：每个 Skill / MCP 注册到 Hub 时，声明它能提供的 Widget。
   - 飞书 MCP → 「群聊待回复」列表；GitHub MCP → 「PR / Issue」列表
   - 调研 Skill → 「来源与发现」；巡检 Skill → 「异常趋势」；风险评估 Skill → 「风险事项」
2. **Bot 构建时组装**：根据 prompt（角色、目标）与已装能力，挑选、排序 Widget，并选出核心指标作为抬头，生成 Spec 存入 Bot 档案。
3. **能力变化 → 仪表盘更新**：安装或卸载 Skill/MCP 时重新组装；用户也可以在对话中调整（「把运行记录放到最上面」——后续版本）。
4. **通用 Widget**：每个 Bot 都有「待你处理」「运行记录」「最近成果」；主 Bot 的仪表盘汇总全部 Bot（待你处理、你的 Bot、完成情况、运行记录）。

```ts
interface DashboardSpec {
  headline: { title: string; subtitle: string };
  widgets: { id: string; kind: WidgetKind; title: string; source: 'core' | `skill:${string}` | `mcp:${string}`; span: 1 | 2 | 3 }[];
}
```

## 5. 关键流程

### 5.1 新建 Bot
「+」打开「新建智能体，完成任务或项目」弹窗，分左右两栏：
- **左：自己创建**。只需起名、选形状和颜色，点「创建」。不配置 prompt、Skill、MCP：**Bot 在工作中自主添加、移除自己需要的 Skill 和 MCP**，工作台随能力变化。
- **右：推荐**。市场里尚未添加的热门专家和专家团，一键添加（连同依赖的 Skill / MCP）。

创建后 Bot 出现在 Bot 栏并成为当前 Bot，并**主动开场**：先打招呼、说明能做什么，再附一张选择卡「你希望我先帮你做什么？」，给出 A / B / C 三个起步任务和 D「其他，我直接说」。选一项即作为第一项任务交给 Bot；选过后卡片锁定并标出所选项。从市场添加的专家 / 专家团也用同样的开场。原型按名称与角色关键词给出选项，之后由模型根据角色生成。

专家管理里的技能、连接器、成员为**只读**：由 Bot 在工作中自主添加或移除；用户只能查看、删除记忆、删除 Bot。

### 5.2 新建群聊（专家团）
Bot 管理 →「新建群聊」→ 选成员 Bot → 群聊作为一个 Bot 出现在 Bot 栏；对话中显示各成员发言，仪表盘汇总成员状态。

### 5.3 对话中创建能力（下一版本）
用户提出需求 → Bot 发现缺少能力 → 提议创建 Skill / MCP 并生成草稿 → 沙箱试跑 → 用户确认 → 发布到 Hub 并绑定到 Bot → 其他 Bot 可复用。
v0.3 原型先提供 Hub 中的「创建 Skill」「接入 MCP」表单。

### 5.4 治理
- Skill：版本、负责人、使用它的 Bot、调用次数、失败率。
- MCP：凭证托管（Vault，凭证不进入 Bot 运行环境）、工具清单、启停、使用它的 Bot。
- Bot：记忆逐条查看与删除、已装能力、运行记录。

## 6. Agent Market（市场与插件）

### 6.1 定位
Agent Market 是独立的管理后台，集中上架 **专家、专家团、Skill、MCP**。它同时承担两件事：
- 给 AgentOS 用：浏览、添加，一键实例化成自己的 Bot 或能力；
- 给其他产品用：每个条目都能作为**插件**接入第三方 Agent 或产品。

入口：工作空间右上角头像菜单 →「市场」，跳转到独立页面（原型地址 `?view=market`）。

### 6.2 定义与实例分开
- **市场里上架的是「定义」**：无状态、可移植，只描述角色、所需能力和成员分工，不含记忆和对话。
- **AgentOS 里运行的是「实例」**：添加后变成有记忆、对话、工作台、运行记录的 Bot。实例记录来源（`sourceId`）。
- 一句话：**定义可移植，实例有状态。** 第三方按专家团的思路使用定义，AgentOS 按 Bot 的思路运行实例，两者不冲突。

| 条目 | 定义内容 | 添加到 AgentOS 后 |
|---|---|---|
| 专家 | 角色 prompt、所需 Skill / MCP、头像 | 一个 Bot；缺的 Skill / MCP 一起添加 |
| 专家团 | 成员专家、分工 | 一个群聊 Bot；已添加的成员专家复用，缺的新建 |
| Skill | SKILL.md（开放格式） | 账号级 Skill，可装给任意专家 |
| MCP | MCP 服务地址、工具、凭证方式 | 账号级 MCP；需凭证的由管理员审批、在 Vault 配置 |

### 6.3 作为插件接入其他产品
同一个条目提供两种接入方式：
1. **远程调用（推荐、可计费）**：条目对外是一个 MCP 服务，提供「交代任务 / 查询进度 / 取回成果」等工具。背后由 AgentOS 托管运行，记忆、审批、审计都留在企业内。
2. **插件包（下载定义）**：Skill 下载 SKILL.md；专家 / 专家团下载 JSON 清单（`agentos.expert` / `agentos.team`），在对方产品里用对方的模型运行。AgentOS 特有的字段（如头像、工作台布局）放在 `extensions.agentos` 里，第三方可以忽略。

整个市场本身也是一个 MCP 插件：第三方 Agent 可以在对话里搜索、添加和调用市场内容。

### 6.4 来源与治理
- 来源分三层：**官方**（AgentOS 预置）、**企业**（同事发布）、**我的**（个人私有）。
- 生命周期（规划）：草稿 → 试用 → 我的 → 提交到企业市场 → 管理员审核 → 上架；版本更新提醒与下架。
- MCP 涉及凭证和数据权限：正式环境中普通用户只能「申请使用」，由管理员审批。

### 6.5 原型范围
已做：市场页（分类、来源筛选、搜索、详情）、添加到 AgentOS（连带依赖、专家团连带成员）、远程调用配置与插件包下载、市场 MCP 配置。
未做：发布到市场、审核流程、版本管理、真实的远程调用与计费。

## 7. v0.3 原型范围与边界

**做**：新布局；主 Bot + 示例 Bot + 示例群聊；Spec 生成与 Widget 组件库；Bot 栏的当前态与工作中态；三个 Hub 的列表、详情、安装 / 卸载、创建表单；本地保存。

**不做**：真实模型调用、真实 MCP 连接、后端（以后接入 KodaX runtime）、对话中创建能力的完整流程、多人协作与权限。Bot 回复由前端定时器模拟。

## 8. 待定问题

1. 长期使用后对话很长：靠记忆 + 检索，还是保留轻量的话题折叠？
2. Skill / MCP 的创建面向业务人员（对话生成）还是开发者（写代码）？
3. 群聊里谁来派活：群主 Bot 调度，还是用户 @ 谁谁动手？
4. Bot 的归属与记忆分层：个人 Bot 与团队 Bot 如何划分？
5. 专家 / 专家团的定义格式：兼容 WorkBuddy 等已有格式，还是按开放标准自定义并提供导入转换？
6. 托管调用的授权与计费方式：第三方接入是否需要企业授权，按什么计费？
