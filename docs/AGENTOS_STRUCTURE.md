## 0. 一句话

**AgentOS 是面向企业的智能体管理平台。** 用户在网页上创建智能体来完成任务；智能体在工作中长出技能和连接器，用顺手了就沉淀为专家，审批后发布到公司的 Agent Market，全公司都能招募。底座是 KodaX。

和 Grok Bot 一样，**智能体是唯一的基本单位**：一段对话就是一个智能体，不再区分项目、会话、任务。

| 对外名称 | 是什么 |
|---|---|
| 智能体 | 用户创建的最小单位：有身份、记忆、面板和工作区，在干活的实例 |
| 智能体群 | 多个智能体协作，本身也作为一个智能体出现 |
| 专家 | 智能体沉淀出来的定义包：提示词 + 技能和连接器清单 + 面板模板，不带记忆和环境 |
| 专家团 | 智能体群沉淀出来的定义包 |
| 企业效能管理智能体 | 主智能体，就是首页，汇总全部智能体，也是治理入口 |
| 专家管理 / 技能管理 / 连接器管理 | 三个系统智能体，分别管理智能体与专家、技能、连接器 |

| 层 | 和 Grok Bot 比 |
|---|---|
| 交互层 | **只有网页端，面向企业。** 多了「左对话、右面板」的布局、通知中心的审批卡片和公司 Agent Market |
| 智能体层 | 和 Bot 一样有身份、记忆、Routine；**多了面板和托管工作区** |
| 能力层 | 对应 Grok Bot 的账号层，同样组织共享；**区别是按智能体授权**，另外多了专家库 |
| 执行层 | **不做虚拟机。** 按任务类型走四条路径之一，见第 5 节 |
| 底座 | Grok Bot 的底座是 Cursor，我们的是 KodaX |

## 2. 什么共享、什么归智能体

原则沿用 Grok Bot：**能力可以广泛共享，上下文留给需要它的岗位。** 我们多了一条：**共享不等于默认可用，每个智能体只拿到被授权的那部分。**

```text
┌─ 组织级：共享，但要授权 ─────────────────────────────────────────────────┐
│ ┌───────────┐  ┌───────────┐  ┌───────────┐  ┌───────────┐  ┌──────────┐ │
│ │ SkillHub  │  │  MCPHub   │  │   Vault   │  │  专家库   │  │  Widget  │ │
│ │   技能    │  │  连接器   │  │   凭证    │  │   专家    │  │  组件库  │ │
│ └───────────┘  └───────────┘  └───────────┘  └───────────┘  └──────────┘ │
└──────────────────────────────────────────────────────────────────────────┘
                                     │ 只拿到被授权的那部分
                                     ▼
┌─ 智能体级：各自拥有，记忆和工作区互不相通 ───────────────────────────────┐
│ ┌─ 调研智能体 ───────┐   ┌─ PPT 智能体 ───────┐   ┌─ 查询智能体 ───────┐ │
│ │ 身份、提示词       │   │ 身份、提示词       │   │ 身份、提示词       │ │
│ │ 记忆               │   │ 记忆               │   │ 记忆               │ │
│ │ Routines           │   │ Routines           │   │ Routines           │ │
│ │ 面板               │   │ 面板               │   │ 面板               │ │
│ │ 托管工作区         │   │ 托管工作区         │   │ 托管工作区         │ │
│ └────────────────────┘   └────────────────────┘   └────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────┘
                                     │ 几个智能体组成一个群
                                     ▼
┌─ 智能体群 ───────────────────────────────────────────────────────────────┐
│ 共享：这个项目的上下文、群面板                                           │
│ 不共享：每个成员仍保留自己的记忆和工作区                                 │
└──────────────────────────────────────────────────────────────────────────┘
```

为什么要多一层授权：Grok Bot 面向个人，允许的连接器对用户的每个 Bot 都可用。企业里，查询智能体能查人员库，不代表 PPT 智能体也能查。

## 3. 一个智能体的内部结构

```text
┌─ 触发 ───────────────────────────────────────────────────────────────────┐
│           用户消息 / 面板操作 / 群聊消息 / Routine 定时或事件            │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 一个智能体 ─────────────────────────────────────────────────────────────┐
│ ┌───────────────┐ ┌───────────────┐ ┌───────────────┐ ┌────────────────┐ │
│ │     身份      │ │     记忆      │ │   Routines    │ │      面板      │ │
│ │   名字 头像   │ │     偏好      │ │   长期职责    │ │ Dashboard Spec │ │
│ │    提示词     │ │   过往工作    │ │               │ │  Widget 布局   │ │
│ │     边界      │ │   对话历史    │ │               │ │    数据绑定    │ │
│ └───────────────┘ └───────────────┘ └───────────────┘ └────────────────┘ │
│                                    │ 装进上下文                          │
│                                    ▼                                     │
│                 ┌──────────────────────────────────────┐                 │
│                 │               推理循环               │                 │
│                 │         运行在 KodaX runtime         │                 │
│                 └──────────────────────────────────────┘                 │
└──────────────────────────────────────────────────────────────────────────┘
                                     │ 按需调用
        ┌──────────────────┬─────────┴─────────┬──────────────────┐
        ▼                  ▼                   ▼                  ▼
┌───────────────┐  ┌────────────────┐  ┌───────────────┐  ┌───────────────┐
│  已授权技能   │  │  已授权连接器  │  │   临时沙箱    │  │     委派      │
│   SkillHub    │  │ MCPHub + Vault │  │  算、做文件   │  │  CLI / Space  │
└───────────────┘  └────────────────┘  └───────────────┘  └───────────────┘
        └──────────────────┴─────────┬─────────┴──────────────────┘
                                     │
                                     ▼
┌──────────────────────────────────────────────────────────────────────────┐
│                  产出：对话回复 + 面板更新 + 工作区文件                  │
│                    同时写回这个智能体的记忆和运行记录                    │
└──────────────────────────────────────────────────────────────────────────┘
```

和 Grok Bot 的 Bot 相比，多了两样东西：

- **面板（Dashboard Spec）**：这个智能体的工作台长什么样，由它的能力决定。详见第 6 节。
- **托管工作区**：文件、产物、运行记录都存在这里，起的是 Grok Bot 那台云电脑的「持久」作用，但每个智能体单独一份。

## 4. 一个智能体怎么构建出来

有两种起点：**从空白开始，或者招募一个专家。**

```text
┌─ 1 用户 > 首页 ──────────────────────────────────────────────────────────┐
│ 新建智能体                                                               │
└──────────────────────────────────────────────────────────────────────────┘
                                     │ 两种起点
                   ┌─────────────────┴──────────────────┐
                   ▼                                    ▼
  ┌─ 方式 A：从空白开始 ────────────┐  ┌─ 方式 B：招募专家 ──────────────┐
  │ 只起名、选形状和颜色            │  │ 从专家库或市场选一个专家        │
  │                                 │  │                                 │
  │ 不配提示词、技能、连接器        │  │ 带入提示词、技能清单            │
  │ 在工作中自己长出能力            │  │ 和面板模板；记忆从空开始        │
  └─────────────────────────────────┘  └─────────────────────────────────┘
                   └─────────────────┬──────────────────┘
                                     │
                                     ▼
┌─ 2 用户 > 智能体 ────────────────────────────────────────────────────────┐
│ 交代任务                                                                 │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 3 智能体 ───────────────────────────────────────────────────────────────┐
│ 缺技能：向 SkillHub 申请，或在对话里创作一个                             │
│ 缺连接器：向 MCPHub 申请，凭证由管理员在 Vault 配置                      │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 4 系统 ─────────────────────────────────────────────────────────────────┐
│ 能力变化后，面板自动重新组装                                             │
│ 例：装上搜索技能，面板多出搜索框                                         │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 5 用户 > 智能体 ────────────────────────────────────────────────────────┐
│ 做法跑通了：存为技能                                                     │
│ 需要长期做：设成 Routine                                                 │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌──────────────────────────────────────────────────────────────────────────┐
│                 用顺手了，就可以沉淀为专家（见第 9 节）                  │
└──────────────────────────────────────────────────────────────────────────┘
```

- **招募专家**的意思是：用专家的定义新建一个智能体实例。实例带着专家的提示词、技能清单和面板模板，**记忆从空开始**；连接器由使用者或所在部门重新授权，不继承原作者的凭证。
- **从空白开始**不需要任何配置：智能体在工作中自己申请、添加、移除技能和连接器，面板跟着变化。
- 除了在新建时招募，**也可以把专家招募进一个智能体群**当成员（见第 8 节）。

## 5. 一次任务怎么执行

从上往下读：交代目标和边界 → 加载能力 → 按任务类型走四条路径之一 → 治理 → 写回。

```text
┌─ 1 用户 > 智能体 ────────────────────────────────────────────────────────┐
│ 在对话里交代目标，或在面板上操作                                         │
│ 同时写清边界：例如只读、不得对外发送                                     │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 2 智能体 ───────────────────────────────────────────────────────────────┐
│ 加载身份、记忆、已授权的技能和连接器                                     │
└──────────────────────────────────────────────────────────────────────────┘
                                     │ 按任务类型分流
        ┌───────────────────┬────────┴─────────┬──────────────────┐
        ▼                   ▼                  ▼                  ▼
┌─ 连接器 ───────┐  ┌─ 沙箱 ────────┐  ┌─ CLI ─────────┐  ┌─ Space ───────┐
│ 查、写企业系统 │  │ 算数、做 PPT  │  │ 写代码、运维  │  │ 员工电脑操作  │
│                │  │               │  │               │  │               │
│ MCP 网关       │  │ 临时沙箱      │  │ 另起一次      │  │ 交给          │
│ Vault 取凭证   │  │ 按任务拉起    │  │ KodaX CLI Run │  │ KodaX Space   │
│ 智能体拿不到   │  │ 用完销毁      │  │ 回传分支报告  │  │ 需本人授权    │
└────────────────┘  └───────────────┘  └───────────────┘  └───────────────┘
        └───────────────────┴────────┬─────────┴──────────────────┘
                                     │
                                     ▼
┌─ 治理 ───────────────────────────────────────────────────────────────────┐
│ 敏感动作（发送、删除、改生产、查敏感数据）先审批，并记入审计日志         │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 3 智能体 ───────────────────────────────────────────────────────────────┐
│ 产物存进托管工作区，写回记忆和运行记录                                   │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 4 智能体 > 用户 ────────────────────────────────────────────────────────┐
│ 左边回复，右边面板更新；需要人决定的，发审批卡片                         │
└──────────────────────────────────────────────────────────────────────────┘
```

执行层不做虚拟机，四条路径各自的用途：

| 路径 | 什么时候用 | 对应 Grok Bot |
|---|---|---|
| 连接器 | **主路径**：企业的活大多是查系统、写系统 | 同样是连接器优先 |
| 临时沙箱 | 需要执行代码：做 PPT、跑数据分析。按任务拉起，用完销毁 | Grok Bot 在常驻云电脑上执行 |
| KodaX CLI | 编码、运维任务，另起一次 Run | 委派给 Cursor Cloud Agents |
| KodaX Space | 必须操作员工电脑或浏览器时，需要本人授权 | Grok Bot 在云电脑上用 computer-use |

**默认不做浏览器自动化。** 有连接器就走连接器；没有连接器又必须操作网页时，交给 KodaX Space。

## 6. 面板：左边对话，右边可交互的工作台

### 6.1 面板放在哪一层

**定义归智能体层，渲染归交互层，数据和动作来自能力层。**

| 层 | 负责什么 |
|---|---|
| 交互层 | Widget 组件库、左右布局、渲染、筛选和输入 |
| 智能体层 | Dashboard Spec：放哪些 Widget、怎么排、绑定哪个技能或连接器、用户调过的布局 |
| 能力层 | 每个技能和连接器声明自己能提供哪些 Widget，以及背后的数据和动作 |

这样拆的好处：

- 面板跟着智能体走，沉淀为专家时**面板模板能一起带走**；
- 渲染统一由组件库负责，**智能体只生成声明式的 Spec，不生成代码**，视觉一致，也方便治理和做版本管理。

### 6.2 两类 Widget

```text
┌─ 两类 Widget ────────────────────────────────────────────────────────────┐
│ ┌─ 看 ────────────────────────────┐  ┌─ 做 ────────────────────────────┐ │
│ │ 展示型 Widget                   │  │ 操作型 Widget                   │ │
│ │                                 │  │                                 │ │
│ │ 指标、趋势                      │  │ 表单、搜索框                    │ │
│ │ 列表、运行记录                  │  │ 带按钮的表格                    │ │
│ │ 成果、产物预览                  │  │ 筛选、确认                      │ │
│ └─────────────────────────────────┘  └─────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 来源 ───────────────────────────────────────────────────────────────────┐
│ Widget 从哪来：每个技能、连接器在 Hub 注册时，声明自己能提供哪些 Widget  │
│ 智能体装上能力时，系统按模板挑选、排序，生成 Dashboard Spec              │
└──────────────────────────────────────────────────────────────────────────┘
```

借鉴 Claude Dashboards 的三点：每个 Widget 写明数据来源，显示最后刷新时间，点 Widget 可以直接追问智能体。Claude Dashboards 以展示为主；**我们多了操作型 Widget**，这是 B 端场景真正需要的。

### 6.3 操作型 Widget 的两种走法

以部署到公安的查询智能体为例：输入身份证号，查这个人有没有犯罪记录。

```text
┌─ 查询智能体 ─────────────────────────────────────────────────────────────┐
│ ┌─ 左：对话 ─────────────────┐  ┌─ 右：面板 ───────────────────────────┐ │
│ │ 用户：帮我查一下           │  │ 身份证号 [__________]                │ │
│ │ 这个人的记录               │  │ 查询事由 [__________]                │ │
│ │                            │  │ [ 查询 ]                             │ │
│ │ 智能体：已查询，           │  │                                      │ │
│ │ 结果在右侧                 │  │ 结果：脱敏展示                       │ │
│ └────────────────────────────┘  └──────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────┘
                                     │ 操作型 Widget 声明走哪条路
                   ┌─────────────────┴──────────────────┐
                   ▼                                    ▼
  ┌─────────────────────────────────┐  ┌─────────────────────────────────┐
  │ 路径 A：直接调用                │  │ 路径 B：交给智能体              │
  │                                 │  │                                 │
  │ 表单直连连接器                  │  │ 表单变成结构化消息              │
  │ 不经过大模型                    │  │ 智能体推理后再调用              │
  │ 快、结果确定                    │  │ 适合要分析、要追问的            │
  │ 适合查询、登记类                │  │                                 │
  └─────────────────────────────────┘  └─────────────────────────────────┘
                   └─────────────────┬──────────────────┘
                                     │
                                     ▼
┌─ 治理 ───────────────────────────────────────────────────────────────────┐
│ 两条路都经过：权限校验、查询事由、审批（按需）、脱敏、审计日志           │
│ 结果同时写进对话时间线，左右两边保持一致                                 │
└──────────────────────────────────────────────────────────────────────────┘
```

- **查询、登记类走路径 A。** 结果必须确定，不能让大模型「理解」后再改写，而且又快又便宜。
- **要综合分析的走路径 B。** 比如「这个人最近有什么异常」，需要智能体汇总多个来源。
- **两条路的结果都写进对话时间线。** 左右两边始终一致，智能体也知道用户在面板上做了什么，后续可以接着追问。
- **敏感查询的治理是卖点。** 每次查询都要填事由、留痕，结果默认脱敏展示。

## 7. Routine：没人叫也会干活

沿用 Grok Bot 的设计：一条 Routine 只属于一个智能体，给它一份长期职责。

```text
┌─ 触发源 ─────────────────────────────────────────────────────────────────┐
│ 定时：每天、每周                                                         │
│ 事件：飞书、GitHub、工单系统等（经 MCPHub 接入）                         │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ Routine ────────────────────────────────────────────────────────────────┐
│ 只属于一个智能体，带着这条 Routine 的工作说明唤醒它                      │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 智能体 ─────────────────────────────────────────────────────────────────┐
│ 按技能执行，结果写进对话时间线，面板同步更新                             │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                   ┌─────────────────┴──────────────────┐
                   ▼                                    ▼
  ┌─────────────────────────────────┐  ┌─────────────────────────────────┐
  │           需要人判断            │  │            正常完成             │
  │       通知中心出审批卡片        │  │      结果留在对话和面板里       │
  └─────────────────────────────────┘  └─────────────────────────────────┘
```

- 外部事件经 MCPHub 接入，和连接器走同一套授权。
- Routine 的结果同时出现在对话里和面板上，比如每天早上的简报直接显示在面板的「最近成果」里。

## 8. 智能体群

沿用 Grok Bot：群聊提供共享上下文，每个成员保留自己的记忆。我们多了两点：**群有自己的面板，汇总成员状态；可以把专家招募进群。**

│      └────────┘  │ 负责拆解和协调 │  └────────────┘  │   新实例   │      │
│                  └────────────────┘                  └────────────┘      │
│                                                                          │
│            ┌────────────────────────────────────────────────┐            │
│            │       群面板：汇总成员状态、待处理、成果       │            │
│            └────────────────────────────────────────────────┘            │
└──────────────────────────────────────────────────────────────────────────┘
                                     │ 群里开始干活
                                     ▼
┌─ 1 用户 > 群主 ──────────────────────────────────────────────────────────┐
│ 出一份竞品分析，周五前                                                   │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 2 群主 > 调研智能体 ────────────────────────────────────────────────────┐

招募进群的专家同样是一个新实例，从空记忆开始，有自己的工作区。

## 9. 沉淀为专家，发布到市场

**智能体 = 专家（定义）+ 记忆 + 环境。** 所以沉淀就是去掉记忆和环境，只留定义，不需要沉淀任何工程化能力。这一点参考了 WorkBuddy：它的专家是「人设 + 方法论 + 工具链」，不带记忆，分享出去成员拿到的也是副本。

```text
┌─ 智能体：在干活的实例 ───────────────────────────────────────────────────┐
│ 身份、提示词                                                             │
│ 技能、连接器（已授权）                                                   │
│ 面板（含数据和调整）                                                     │
│ Routines                                                                 │
│ 记忆                                                                     │
│ 托管工作区、运行记录                                                     │
└──────────────────────────────────────────────────────────────────────────┘
                                     │ 沉淀为专家
                                     ▼
┌─ 拆分 ───────────────────────────────────────────────────────────────────┐
│ ┌─────────────────────────────────┐  ┌─────────────────────────────────┐ │
│ │ 留下：定义                      │  │ 去掉：记忆和环境                │ │
│ │                                 │  │                                 │ │
│ │ 身份、提示词                    │  │ 记忆、对话历史                  │ │
│ │ 技能、连接器清单                │  │ 工作区文件、运行记录            │ │
│ │ 面板模板                        │  │ 凭证授权                        │ │
│ │ Routine 模板（可选）            │  │ 面板里的实际数据                │ │
│ └─────────────────────────────────┘  └─────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌──────────────────────────────────────────────────────────────────────────┐
│                   专家：一个定义包，不带任何工程化能力                   │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 可选：发布 ─────────────────────────────────────────────────────────────┐
│            提交审批 > 上架公司 Agent Market > 全公司可以招募             │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌─ 别人怎么用 ─────────────────────────────────────────────────────────────┐
│     招募 = 新建一个智能体实例：记忆从空开始，连接器由使用者重新授权      │
└──────────────────────────────────────────────────────────────────────────┘
```

| | 专家（定义包） | 智能体（实例） |
|---|---|---|
| 身份、提示词 | ✅ | ✅ |
| 技能、连接器 | ✅ 只记录需要哪些 | ✅ 已装好、已授权 |
| 面板 | ✅ 模板 | ✅ 外加实际数据和用户调整 |
| Routine | 可选：只带模板 | ✅ 实际运行 |
| 记忆 | ❌ | ✅ |
| 工作区、凭证授权、运行记录 | ❌ | ✅ |

- 操作入口：在智能体工作台右上角点「沉淀为专家」（智能体群是「沉淀为专家团」），可以勾选「同时提交发布到企业市场」。
- Agent Market 是**公司级**的，审批通过后全公司都能招募。
- 第一版**不做**「从记忆里提炼经验写进提示词」。以后要做的话需要人工审核，避免把敏感数据带进市场。

## 11. 安全边界

这是和 Grok Bot 差别最大的地方。Grok Bot 官方明确说，同一用户的 Bot 之间不是安全边界，因为它们共用一台电脑、文件、登录态和凭证。我们按智能体隔离。

```text
┌─ 企业（AgentOS 租户） ───────────────────────────────────────────────────┐
│ ┌─ 部门 A ───────────────────────┐           ┌─ 部门 B ─────────┐        │
│ │ ┌─ 智能体 1 ─┐  ┌─ 智能体 2 ─┐ │           │ ┌─ 智能体 3 ─┐   │        │
│ │ │ 记忆       │  │ 记忆       │ │           │ │ 记忆       │   │        │
│ │ │ 工作区     │  │ 工作区     │ │   各自    │ │ 工作区     │   │        │
│ │ │ 授权清单   │  │ 授权清单   │ │   隔离    │ │ 授权清单   │   │        │
│ │ └────────────┘  └────────────┘ │   <───>   │ └────────────┘   │        │
│ └────────────────────────────────┘           └──────────────────┘        │
└──────────────────────────────────────────────────────────────────────────┘
                                     │ 调用连接器时
                                     ▼
┌──────────────────────────────────────────────────────────────────────────┐
│              MCP 网关：校验这个智能体是否被授权，再代它去调              │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
┌──────────────────────────────────────────────────────────────────────────┐
│              Vault：凭证只在网关里用，不进智能体、不进沙箱               │
└──────────────────────────────────────────────────────────────────────────┘
```

| 边界 | AgentOS | Grok Bot |
|---|---|---|
| 智能体之间 | ✅ 记忆、工作区、授权清单各自独立 | ❌ 共享电脑、文件和凭证 |
| 凭证 | 只在网关里使用，不进智能体、不进沙箱 | 存在 Cursor 后端，但 CLI 凭证在共享电脑上 |
| 能力 | 按智能体授权 | 允许的连接器对用户的每个 Bot 都可用 |
| 敏感动作 | 审批 + 审计日志 + 脱敏 | Auto Review 审批 |
| 沉淀和发布 | 去掉记忆和凭证，审批后才能上架 | 没有这个环节 |

## 12. 和 Grok Bot 的差异

| # | 差异 | Grok Bot | AgentOS |
|---|---|---|---|
| 1 | 面向谁 | 个人和小团队，桌面、Web、手机 | **企业**，只有网页端；企业级治理和沉淀是必需的 |
| 2 | 能力沉淀 | 技能可以存下来复用 | **智能体可以沉淀为专家**，审批后进公司市场，全公司招募 |
| 3 | 执行环境 | 每用户一台常驻云电脑 | **不做虚拟机**：连接器、临时沙箱、KodaX CLI、KodaX Space 四条路径 |
| 4 | 交互方式 | 对话为主，回复里带卡片 | **左对话、右面板**，面板按能力生成，可以直接操作 |
| 5 | 能力授权 | 账号内全部共享 | 组织共享，**按智能体授权** |
| 6 | 隔离 | Bot 之间不隔离 | 智能体之间隔离 |
| 7 | 全局视图 | 刻意不做看板，由 Bot 协调 | 企业效能管理智能体提供治理视图 |

**原样沿用 Grok Bot 的部分**：智能体是唯一的基本单位；记忆按智能体隔离；群聊共享上下文、成员保留各自记忆；Routine 给智能体长期职责；连接器优先；敏感动作要人确认。
